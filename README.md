# autumn26_hack

Хакатон осень 2026, кейс про прогноз денег для малого бизнеса. Команда: ПАРАМАТЕМАТИКИ

Сервис берёт банковскую выписку компании, раскладывает операции по категориям, находит регулярные платежи (зарплата, налоги, аренда и т.д.), прогнозирует остаток на счёте на 30 дней и предупреждает, если может не хватить денег: когда, сколько и с какой вероятностью.

## Как запустить

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Датасет из чата распаковать в папку `data/` (должны получиться `data/all_operations.csv`, `data/companies.csv`, `data/statements/`). Не добавляли сюда его.

Свою выписку можно загрузить прямо в приложении: слева "Загрузить свой CSV". Формат как в датасете кейса (разделитель `;`).

## Что есть в приложении

- **Прогноз** - график остатка с прогнозом на 30 дней, предупреждение о разрыве (почему и что делать), ближайшие платежи, категории. Слева можно добавить своё событие ("клиент заплатит 300 000 20-го"), прогноз сразу пересчитается.
- **Как посчитан прогноз** - расчёт по шагам с цифрами, таблицу по дням можно скачать.
- **Качество прогноза** - бэктест на загруженных данных: метрики, матрица ошибок, прогноз против факта.

## Как считаем

1. `data_prep.py` - читаем выписку, убираем дубли и битые строки, строим таблицу по дням. Пропуски в выписке ищем по остатку: если вчерашний остаток + приход - расход не равен сегодняшнему, значит часть операций пропала. Эти дни в прогноз не берём.
2. `rules_categorizer.py` - категория по ключевым словам в назначении платежа, если назначения нет - по контрагенту. 22 категории, размечено 99.9% операций.
3. `regular_payments.py` - ищем платежи, которые повторяются с ровным интервалом и похожей суммой, и продлеваем их на 30 дней. ЕНП 28-го числа. Сюда же попадают события, которые пользователь ввёл руками.
4. `forecaster.py` - остальные деньги (выручка, закупки, услуги) прогнозируем средним по дню недели за полгода. Разброс (sigma) берём оттуда же.
5. `cashflow_engine.py` - остаток по дням = старт + поток + известные платежи. Коридор ±1.65·sigma·√t. Вероятность уйти в минус считаем через нормальное распределение, предупреждаем с 40%.

Важный момент: в данных владельцы часто сами докладывают деньги на счёт или берут кредит, когда денег не хватает, поэтому реальный остаток почти не уходит в минус. Разрывом мы считаем ситуацию, когда без этих пополнений остаток ушёл бы в минус - о ней и надо предупреждать заранее.

## Проверка качества

`evaluation.py` - бэктест: для каждой компании отматываем время каждые 28 дней, строим прогноз на 30 дней и сравниваем с тем, что было.

```
python evaluation.py data/all_operations.csv
```

На всём датасете (2749 прогнозов, 144 компании, 298 разрывов), порог 0.4:

| Accuracy | Precision | Recall | F1 | ROC AUC | MAE |
|---|---|---|---|---|---|
| 0.88 | 0.48 | 0.70 | 0.57 | 0.91 | 1.23 млн ₽ |

Пойманные разрывы видим в среднем за 12 дней до того, как они случаются. 

Тесты:

```
python -m pytest tests -v
```
